# Как править лид на главной

Инструкция по ручному редактированию первого экрана `index.html`. Файл самодостаточный: вся вёрстка, стили и скрипты в одном документе, сборки нет. Правишь → сохраняешь → открываешь в браузере.

## Карта блока

```
<nav>                          шапка: навигация по разделам и страницам
<header class="hero">
  └── .hero-grid               сетка: 2 колонки + подвал во всю ширину
        ├── .hero-col-main     ЛЕВАЯ:  .kicker → h1 → .tagline
        ├── .hero-col-side     ПРАВАЯ: .photo-frame → .sub
        └── .hero-foot         ПОДВАЛ: .cta слева | .cx-row справа
```

CSS блока — в `<style>`, секция с шапкой комментария `HERO / ЛИД`. Разметка — в теге `header.hero`. Оба места помечены комментариями с указателями.

## Где правится текст

| Что на экране | Где в файле | Ограничение |
|---|---|---|
| Оранжевая строка над заголовком | `<div class="kicker rise">` | одна строка, пункты через `·` |
| Заголовок «Вижу систему целиком…» | `<h1 class="display rise">` | оранжевое слово оборачивается в `<span class="l2">` |
| Лид «Специалист знает детали…» | `<p class="tagline rise">` | **3–4 фразы**, иначе правая колонка проваливается |
| Локация на фото | `<p class="photo-role">` | три `<span>`, разделители `·` между ними |
| Биография «Инженер-теплоэнергетик…» | `<p class="sub rise">` | **2–3 фразы**, иначе правая колонка перегоняет левую |
| Кнопки | `.hero-foot > .cta` | `class="pill hot"` — главная, `class="pill"` — вторичная |
| Контакты | `.hero-foot > .cx-row` | ровно 4 штуки: сетка 2×2 |

## Где правятся размеры

Всё в CSS, секция `HERO / ЛИД`:

| Задача | Свойство | Текущее | Осторожно |
|---|---|---|---|
| Ширина фото и всей правой колонки | `--photo` в `.hero-grid` | `340px` | тянет за собой биографию и колонку контактов в подвале |
| Длина строки лида | `max-width` в `.hero-col-main .tagline` | `42ch` | больше 46ch — строка уходит за 90 знаков |
| Кегль заголовка | `font-size` в `.hero h1` | `clamp(42px,7.2vw,96px)` | — |
| Слов в строке заголовка | `max-width` в `.hero h1` | `17ch` | больше 19ch — строки подходят к фото вплотную |
| Зазор между колонками | `gap` в `.hero-grid`, второе значение | `clamp(32px,4.4vw,64px)` | дублируется в `.hero-foot`, меняй в обоих |
| Расстояние фото → биография | `gap` в `.hero-col-side` | `clamp(18px,2vw,24px)` | — |
| Высота первого экрана | `padding` в `.hero` | `112px 0 88px` | больше 100px снизу — секция «01» уезжает с экрана |

## Частые операции

**Сменить фото.** Замени `assets/portrait-560.jpg` и варианты `-400`, `-760`. Пропорции строго **4:5**, лицо в верхней трети кадра — `object-position:50% 12%` кадрирует по этой логике. Если пропорции другие, поправь `aspect-ratio` в `.photo-frame`.

**Убрать фото.** Удали весь `.hero-col-side` и замени `grid-template-columns` на `minmax(0,1fr)` в двух местах: `.hero-grid` и `.hero-foot`.

**Добавить кнопку.** Новый `<a class="pill">` внутри `.cta` в подвале. Больше трёх кнопок в строке не ставь — они начнут переноситься и подвал раздуется.

**Добавить контакт.** Новый `<span class="cx-item">` с иконкой: `<svg viewBox="0 0 24 24">`, только контур (`stroke`), без `fill`. Размер и цвет задаёт CSS. При пятом контакте сетка 2×2 станет 2×3 — либо ставь шестой для симметрии, либо переведи `.hero-foot .cx-row` в три колонки.

**Добавить страницу в навигацию.** Только в `<div class="nav-links">` в шапке. В лид ссылки на страницы не добавляются — там были шесть таких ссылок, они дублировали шапку и карточки в «Артефактах».

## Правило распределения ссылок

Каждая ссылка живёт в одном месте по назначению:

| Место | Что | Пример |
|---|---|---|
| Шапка | разделы `#anchor` и страницы `*.html` | Ценность, SorterLab, Опыт |
| Лид, подвал слева | действия | Смотреть артефакты, Написать в Telegram |
| Лид, подвал справа | контакты | GitHub, Telegram, почта, телефон |
| Карточка артефакта | ссылка на этот артефакт | Открыть кейс, Репозиторий |
| Футер страницы | те же 4 контакта, что в лиде | — |

Контактов в шапке нет намеренно: `@Evandrus` иначе появляется четыре раза на одном экране.

## Что проверить после правки

```bash
# рендер в PNG, посмотреть глазами
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --window-size=1440,1100 \
  --screenshot=/tmp/check.png "file://$PWD/index.html"

# мобильная раскладка
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --window-size=390,1600 \
  --screenshot=/tmp/check-mobile.png "file://$PWD/index.html"
```

Три вещи, которые ломаются чаще всего:

1. **Колонки разъехались по высоте.** Смотри, не добавились ли кнопки в `.hero-col-main` и не разросся ли текст биографии.
2. **Текст биографии не совпал с левым краем фото.** Линейка слева от биографии — псевдоэлемент `::before` с `left:-17px`, а не `padding-left`. Если поставить padding, текст съедет на 16px правее кадра.
3. **Контакты уехали с оси.** `.hero-foot` должен иметь ту же `grid-template-columns`, что и `.hero-grid`.

## Публикация

```bash
git add index.html
git commit -m "правка текста лида [norelease]"
git push origin main
```

Суффикс `[norelease]` обязателен для правок контента: без него `.github/workflows/auto-release.yml` создаст новый релиз. Pages пересобирается 30–40 секунд.
